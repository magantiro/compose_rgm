# T4 zero-oracle route-policy comparison

## Identity and scope

The scientific problem is complete executable-program proposal from an exact
source molecule. The output is a ranked pool of complete endpoints obtained by
the existing Dynamic COMPOSE generic compiler under three modules, 32
primitives, eight blocks, and 40 active atoms. The claim under test is whether
source-conditioned complete-candidate ranking improves route recovery over a
source-balanced marginal, without loading a teacher endpoint or executable
teacher route at test time.

This is answer-known T4 development evidence. It makes zero docking and task
oracle calls. It does not alter or qualify a scored controller.

## Frozen grouped evaluation

The 15 source molecules form three source-group folds. Fold `i` holds out
`source_idx == i`, which is one source from each of the five proteins. Every
route from one source remains in the same fold. All marginals, binding
prototypes, normalizers, actors, and ranker coefficients are fit on the other
ten sources.

The comparison uses 128 attempts per held-out source and 32 generic negative
attempts per training source. Every policy keeps a 0.10 generic exploration
floor. The marginal and hybrid use the same generated test candidate panel,
which isolates the effect of complete-candidate ranking. The current actor uses
its own generator with the same attempt limit and common compiler/executor
support.

Training positives receive equal total weight per source and then per route.
Pairwise ranker negatives divide that route's weight equally. The unchanged
actor baseline retains its existing source-balanced decision fit so that it
remains the current actor-plus-prototype baseline rather than a redesigned
model.

## Policies

1. `generic_marginal` fits only source-balanced module-family and stopping-depth
   frequencies. Its module order and binding are generated by the generic
   Dynamic-v1 compiler.
2. `context_module_prototype` is the current
   `RouteDistilledProgramPolicy`: molecule-to-option actor, manual
   option-to-family mapping, module-count marginal, and aggregate 18-field
   binding prototypes.
3. `graph_contrastive_candidate_ranker` is a small linear pairwise ranker over
   bounded complete executable candidates. It uses invariant source, endpoint,
   fingerprint-change, realized-edit, generic module, dependency, depth, stop,
   and remaining-work features. It is goal-free and receives no target label.

The hybrid is deliberately a ranker over bounded executable candidates, not a
new decoder. Its runtime checkpoint contains only numeric shared weights,
training-only normalization moments, an exploration floor, and a hash of the
training procedure.

## Two distinct evaluations

`autonomous_generation` contains no injected teacher endpoint or teacher route.
It is the only endpoint-generation evidence.

`shared_panel_reranking` adds held-out teacher endpoints to the common generic
candidate panel as labeled offline diagnostic rows. It tests ranking only. The
current actor abstains because it exposes option probabilities and aggregate
prototype ranks, not a faithful normalized score over arbitrary complete
routes; most teacher routes also exceed its three-module horizon. No surrogate
score is invented for it.

Both evaluations use exact canonical endpoint recovery and strict radius-two
transformation equivalence from `route_proposal_quality`. They report recall,
precision, reciprocal rank, exact-execution yield, unique yield, and compute at
1, 5, 10, 32, and 128.

## Runtime exclusions

Test generation receives only the exact source graph and a numeric checkpoint.
Runtime checkpoints contain no target/protein name, seed identity, route ID,
teacher endpoint, source molecule, executable route, absolute atom address, or
target-to-program map. All program instances are rebound against the current
graph and exact-executed. The report scans the serialized runtime payloads
against the complete teacher/source/target census and fails closed on a hit.

## Run

Use the qualified RDKit 2024.03.5 environment:

```bash
python -m tools.t4_route_policy_comparison \
  --output diagnostics/t4_route_policy_comparison/attempt_1
```

The runner refuses to overwrite an existing result and publishes a compressed
runtime-model artifact plus a sealed result with source hashes, configuration,
software versions, fold identities, negative findings, and zero-oracle costs.
