# Learned chain-continuation rewrite (`AlkylGraft`) — lipid-native COMPOSE extension

## Why
COMPOSE/RGM generates atom-by-atom. That is the right granularity for drug-like
small molecules (every atom high-information, entangled with ring topology). It is
the *wrong* granularity for lipid **tails**: a C8–C18 alkyl chain is a long,
self-similar, low-information run, and asking an atom-level model to emit it as N
independent `AtomInsert`s makes each step a fresh chance to drift (spurious N/O,
stray C=C). Empirically: de-novo-from-stub gave 1/12 clean tails; seed-from-lead
(tails pre-supplied) gave 10/10.

The fix is **not** deterministic/parametric tails (that is a menu, not a generator).
The fix is to **match generation granularity to the object**: atom-level where
information is dense (the ionizable head — a small-molecule-sized problem the RGM
is already good at), **chain-level where it is self-similar (the tail)**. The tail
distribution stays fully **learned and continuous** — we just let the model emit it
in one high-level move instead of 16 fragile ones.

This makes the generative problem *factorize*:
`P(lipid) = P(head) · P(tail1) · P(tail2 | attachment) · P(linker)` — a
small-molecule head model × low-dimensional learned tail models. Small molecules
give no such factorization; lipids hand it to us. Hence "lipids are easier."

## The rewrite family
Add `AlkylGraft` (and its CTMC reverse `AlkylPrune`) to the rewrite algebra.

```
AlkylGraft(
    anchor: int,              # existing carbon to grow from
    run: tuple[int, ...],     # per-new-bond order along the run, e.g.
                              #   (1,)*16               -> C16 saturated
                              #   (1,)*8+(2,)+(1,)*8    -> oleyl (one cis-9 C=C)
                              #   (1,)*8+(2,)+(1,)*2+(2,)+(1,)*4  -> linoleyl (cis-9,12)
    geometry: tuple[str, ...] = (),  # cis/trans per double bond (default cis, biologically dominant)
)
AlkylPrune(anchor: int, run_atoms: tuple[int, ...])   # reverse move
```

**Unsaturation is first-class:** it is just the *bond order* of each unit in `run`
(1 = CH2–CH2, 2 = CH=CH), with `geometry` fixing cis/trans. So double bonds at any
position(s), single or poly-unsaturated, are native — oleyl/linoleyl/arachidonyl all
fall out of one move.

**Branching is compositional — no new machinery:** a branch is *another
`AlkylGraft` grafted onto a mid-chain (non-terminal, open-valence) carbon*. The
exact same move, a different anchor. Iso-/2-branched/phytanyl tails emerge by the
model choosing to graft mid-chain. Branches recurse (a branch can itself branch),
so the whole tail alphabet is generated by one self-similar rewrite applied at
different anchors.

Everything — length, where/how many double bonds, whether and where to branch — is a
**distribution the model LEARNS** from the corpus (factorized rate heads below),
never hard-coded and never a discrete menu. Full continuous coverage of the tail
space, generated.

## Generalizing: region-typed generation (heads ≠ tails ≠ linkers)
`AlkylGraft` is the *tail* move. The full picture is **region-typed generation**:
a lipid is partitioned (post-hoc, structurally — via region labels / decompose) into
`head / linker(s) / tail(s)`, and **each region is generated by the move that fits
its nature**, with the model conditioning move-type on the current region (we already
have region-awareness):

| region | nature | generative move |
|---|---|---|
| **head** | small-molecule-like (amines, rings, branch points), high-information | **atom-level RGM rewrites** (AtomInsert, ring ops…). *Heads are NOT chains.* |
| **tail** | self-similar alkyl chain | **`AlkylGraft`** (this doc) |
| **linker** | the joining chemistry | **frozen** (fixed/target-specific) *or* small-region atom-level / motif move (varied) |

### The linker: "labeled after the fact" vs "from synthesis"
Two ways a linker arises, and the resolution to whether they differ:
- **Labeled-after-the-fact (BEAE):** the enamine-ester is *not* a reagent; it forms
  in-situ from the aza-Michael and we label that region structurally on the finished
  molecule (`beae_linker_atoms` via SMARTS). There is no "linker block" to insert.
- **From synthesis:** the linker is a real bifunctional reagent (ester, disulfide,
  carbonate…) — an actual building block.

**For GENERATION they are the same**, and that is the nice part: the generator always
works from **structure + region labels**, never from synthesis history. We label the
region on the graph and either freeze it or generate region-appropriately. So BEAE's
"emergent, labeled" linker and a "reagent" linker flow through identical machinery.

**Where the distinction *does* live is synthesizability**, and it is handled by one
concept — **the linker defines the *attachment points* and the *reactive-compatibility
constraints* for head and tails.** BEAE's frozen linker carries the enamine N (head
attaches here, and must be an amine to have formed via aza-Michael) and the two ester
carbonyls (tails attach here). Generating head/tails *at the labeled attachment points*
(`beae_attachment_points`) with the right reactive context keeps every candidate
synthesizable-by-that-route **by construction** — whether the linker was a reagent or
labeled post-hoc. A reagent linker works the same way: it, too, just specifies
attachment points + required reactive groups.

So the general contract: **region labels are a post-hoc structural partition used to
(1) condition the generator and (2) target/freeze/attach; generation is region-typed;
the linker (however it arose) supplies attachment points + compatibility, which is what
keeps outputs real.** Everything composes; nothing needs to know how the molecule was
originally made.

## Where it plugs into COMPOSE (integration surface)
1. **operators/tracelets** — define `AlkylGraft`/`AlkylPrune` dataclasses + `apply_*`
   (add `length` NULL-slot carbons as a chain from `anchor`, single bonds, terminal
   CH3; update implicit-H/valence). Index-stable like the other micro-ops.
2. **fiber (`_candidate_actions`)** — enumerate: for each eligible carbon anchor
   (open valence), for length ∈ 1..L_MAX, emit a graft. Reverse: prune pendant runs.
3. **factorized rate model** — new factorized head predicting the graft rate as
   `rate(anchor) · P(run | anchor, ctx)`, where `P(run)` factorizes over per-unit
   choices `{continue-saturated, continue-unsaturated(cis/trans), terminate}` — so
   the model learns **length and unsaturation pattern jointly**. Branching needs
   *no* extra head: it is a graft at a non-terminal anchor, so it is already covered
   by `rate(anchor)` ranging over mid-chain carbons. One head, whole tail alphabet.
4. **teacher-path decomposition** — when compiling a corpus lipid's teacher program,
   emit tails as **single `AlkylGraft` moves** (identify linear alkyl runs off the
   head/linker via region labels) instead of atom-by-atom, so training data uses the
   new move and the model learns to generate via grafts. Reverse-consistent with the
   CTMC (graft ↔ prune) for detailed-balance / Poisson-Bregman loss.
5. **sampler** — no change beyond recognizing the new action (rate → exponential
   waiting time → apply), same as every other rewrite.

## Correctness / framework fit
- CTMC balance: `AlkylGraft` is paired with `AlkylPrune` so the generator/teacher
  compilation stays reversible, exactly like insert/delete pairs today.
- Legality lives in the executor (open-valence anchor, valence-valid result), so the
  sampler cannot emit illegal chains — same contract as the existing operators.
- Nothing about the head or linker machinery changes; this is purely an additional
  legal move. Region-awareness already tells the model *where* a tail is.

## Payoff
- **De-novo tails become reliable** (clean chains by construction, few moves, no drift).
- **Full-distribution coverage** of tail length/saturation/branching, learned — not
  discrete enumerated points.
- **Efficiency**: a C16 tail = 1 move, not 16 — training and sampling both cheaper.
