# Region replacement development option

Scope: optional proposal-channel repair for the existing WHERE/WHAT/HOW
controller. The platform remains an executable stochastic molecular process,
not a fragment dictionary. This change tests whether constructive replacement
can escape the observed 39–40-atom incumbent population. It is not a claim of
PMO improvement, general reachability, or exact Doob control.

The existing `rebuild`, `open`, and `shrink` options make one primitive decision.
The new `replace_region:construct:pendant:...` option removes the selected
released material and reconstructs a parameterized pendant cycle in one
controller decision. Each intermediate is executed through the unchanged
primitive executor. No endpoint insertion or whole-ring deletion is added.

Applicability requires a nonempty released region, a nonempty connected frozen
complement and an existing boundary. The predicted final cardinality must fit
the 40-atom support. Removal samples supported region-local atom deletions;
only if none is executable does it sample a supported cycle opening. Growth
uses the existing RingSpec program. The primitive cap is the released atom count
plus original graph cycle rank plus the ring program length. Completion can
precede this cap. Failure is recorded, not replaced with another option.

The fast channel inherits RingSpec's explicit size 5/6 and C/N/O parameter menu.
It is not all chemistry. Generic primitive editing and the previous options
remain active; WHERE and the frozen learned mark law are unchanged. New
replacement variants share the existing restructure purpose group, with the
existing exploration floor. No docking- or winner-fitted macro weights.

Intermediate benchmark feasibility and task scores do not prune a compound
option. Molecular validity and protected-context checks remain mandatory.
The result is sampled at the option endpoint; later options may retype, grow,
shrink or restructure it. This is a proposal distribution over primitive paths,
not a representation-invariant reweighting of the original molecular kernel.

Acceptance before a bounded scientific run: real-executor construction at the
size ceiling; preserved context and exact lineage across deletion/slot reuse;
lazy/eager row agreement; exact augmented-state resume; rejection of unsupported
applicability; generic support and opt-out behavior preserved. Use focused tests.
No scientific run is authorized by this document alone: its prospective config
must bind inputs, source snapshot, oracle budget, concurrency and stop limit.

## First proposal audit

Twenty independent complete-option draws, four from each of the same five warm
development roots used by the preceding SMC probe. WHERE is unchanged and WHAT
uses the balanced applicability-aware prior with replacement enabled. Do not
force a replacement draw or retry a failed option. Score each unique locked
endpoint with the existing deterministic perindopril MPO oracle; at most twenty
new queries. No within-batch score feedback, no surrogate and no new training.
Reuse historical labels from the prepared artifact without requerying them.

This tests whether the normal proposal law selects and completes replacement,
its score/size/topology consequences, and its cost. A batch with no replacement
draws is inconclusive about replacement capability. It is not a paired optimizer
comparison or evidence of beating IVG. Record every attempt, exact primitive
replay, intended release, realized displacement and ring deltas. The max local
primitive clock is forty; it is a computation cap, not an oracle budget.

Compute census: twenty worker tasks, at most twenty workers plus one driver.
Each worker reserves one CPU and 8 GiB for at most 240 seconds, driver at most
600 seconds. No retries. Expected scientific wall time 2–6 minutes, deployment
separate; estimated cost $0.50–4, not a billing guarantee. Restart unit is one
exact-parent worker, with durable per-primitive receipts and 30-second heartbeat.
The previous complete-option worker probe is the reusable runtime benchmark;
no additional disposable canary or corpus preparation is necessary.

Launch authority: after the dirty-snapshot launch was rejected, the user approved
one scoped checkpoint commit and this twenty-proposal audit. The replacement
launcher now requires a clean committed tree and uses the existing clean-source
revision validator, including exact remote byte checks. Historical uncommitted
snapshot receipts remain unchanged; their exception is not used for this run.

Evidence: the prior six-opportunity SMC experiment is banked in
`diagnostics/pmo_option_particles/`. All three arms retained the same best score;
the measured null motivates this proposal repair but does not prove its benefit.
