# Evolving donor memory, matched broad-controller development

## Question and support

COMPOSE generates source-conditioned, complete supported molecular graphs through
executable edit programs. The platform remains a learned stochastic rewrite
process; this experiment tests one task-specific population controller. The
frozen reference model and production executor are unchanged. Scope remains
the broad-organic, charge-preserving, achiral 40-heavy-atom supported graph space,
with exact persistent-slot states. This is not unconditional generation.

Recent donor programs improved perindopril development best to 0.649519, but
contextual replay lost the prespecified comparison to uniform proposals. Keep
that negative result. The new hypothesis is different: discoveries should become
available as donor components for later branches. A fixed initial donor bank
cannot transfer newly evolved components directly between independent branches.
That is a proposal limitation, not proof of molecular unreachability.

## Frozen recipe before outcomes

Both arms start from the same top 16 canonical-distinct exact states in the latest
completed replay comparison and its initial archive. Labels remain exposed warm
development. Both initially share the original 100 donors plus these 16 parents,
canonical-deduplicated. Initial donor probabilities use inverse score ranks,
mixed with 20% uniform mass. Ties receive the same rank. The same rule applies
in both arms, including the fixed-memory control; this differs from the earlier
uniform-donor controller and must not be silently described as its replication.

Each option draw uses the unchanged broad reference hierarchy with probability
0.5, or a donor replacement program with probability 0.5. A donor draw selects
one canonical donor under the declared prior and independent uniform oriented
single-bridge cuts in source and donor. The replacement compiles to the same
guarded primitive executor with 64 steps and 128 compiler expansions. No endpoint
teleportation, finite whole-ring template vocabulary, new reference training,
endpoint predictor, future-value head or public winner is introduced. Whole-ring
and generic atomic/bond options in the existing reference hierarchy remain active.

The fixed arm retains its initial donor memory. The evolving arm adds only its
own requested, scored endpoints, after all proposals and oracle calls of that
round complete. All scores, including low values, remain eligible with positive
mass. No size, chemistry or score truncation is added. Canonical duplicates do
not multiply donor mass. Exact donor states and origins remain available.

Parent selection is identical: existing archive allocation, one incumbent slot
plus 15 inverse-rank archive draws with a 20% uniform exploration component.
Both arms retain every own requested endpoint in their archives. Neither imports
unrequested molecules from the other arm or a historical-label cache. A shared
candidate is charged once but counted only in arms that requested it. Matching
memory, parent and RNG tasks can share computation. No within-round feedback.

Six rounds, 16 option slots per arm, seed 20261002, maximum 192 new physical
queries. Invalid, unresolved, self and repeated options are recorded and are not
replaced. All novel completed candidates are queried after the round lock.
Historical accounting includes 249455 prescreen labels and 732 development calls.
No new prescreening or public-winner input. This is not official PMO AUC.

## Decision and compute

Primary positive: evolving memory exceeds both the initial 0.649519052838329 and
the concurrent fixed-memory arm's best. That earns one fresh-seed replication,
not a SOTA claim. Report top-ten mean, unique improving endpoints, canonical and
scaffold diversity, intended release versus actual structural/topology changes,
which added donors were actually selected, cumulative queries and timings.
A top-ten-only gain is secondary. A completed null stops this unchanged recipe;
execution failures are inconclusive and recover only missing compatible units.

At most 29 proposal workers and one driver, 1 CPU/8 GiB per container, no GPU.
Worker timeout 180 seconds, driver 900 seconds, no automatic worker retries.
192 worker tasks maximum, theoretical reserved CPU upper bound 9.85 hours;
$10 cap, no concurrent T4 run. Representative prior broad comparison took
350 seconds for four rounds, with approximately 8.6 summed worker seconds per
attempt. Expected 4-12 minutes excluding build. Per-round and per-worker receipts
are restart units; no re-enumeration of compatible completed laws. Deploy and
spawn only after focused checks, input binding and clean committed source.

These are heuristic population proposals and actual-score archive selection,
not an exact original-reference Doob transform, a learned committor, or a
representation-invariant mark controller. The original executor support and
frozen neural law remain separately identified.
