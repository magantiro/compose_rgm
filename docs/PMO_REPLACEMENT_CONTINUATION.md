# Score-informed continuation after region replacement

This bounded warm-development experiment tests whether repeated complete-option
search builds on the preceding replacement products. The output is a retained
archive of scored complete molecular graphs with exact primitive witnesses.
The platform is the frozen COMPOSE editing process, not this particular particle
experiment. No official PMO AUC, blind discovery, or generalization claim follows.

Start both arms from the five original warm roots and all four completed
replacement products from run
`1efb450599f9999cedbb79d65b2e9c2ee296a4c84dd0e6d29975171f0269b032`.
Retain the replacement that reduced its parent's score; do not select starts by
improvement. Preserve exact slot-addressed states, lineage and historical labels.
Do not reconstruct states from SMILES. Historical queries remain development
costs, not free initialization for a benchmark claim.

Nine particles per arm make four additional complete-option decisions. Both
arms use the identical hierarchical proposal B, including replacement, the
unchanged WHERE selector, balanced applicable WHAT prior, generic channel and
existing primitive executor. The local primitive cap is forty. Molecular size
is at most forty, charge and stereochemistry support are unchanged, and the
fast construction menu remains RingSpec's size-5/6 C/N/O parameterization. This
menu is narrower than generic primitive support. No gate is changed.

Reference particles propagate independently. Score-informed particles use the
existing Feynman–Kac update, with q=B and incremental potential
psi_t(x_t)/psi_(t-1)(x_(t-1)). Initial psi is one, intermediate psi is
exp(10*actual_PMO_score), and the exact terminal potential is the same score
transform for both arms. Retain weights between resampling events; systematically
resample only when ESS < N/2, and not at the terminal boundary. Complete options
are indivisible control decisions but their internal states are valid primitive
successors. No intermediate task-value pruning and no surrogate/value head.
This is finite-particle approximate control, not exact molecular-scale Doob
sampling or a qualified future-value estimator.

Lock each complete proposal batch before querying. Canonically deduplicate all
queries and reuse saved actual scores. No result from a batch influences another
proposal in that batch. Identical exact-parent/seed worker tasks are shared
across arms; ancestry divergence causes separate work. Failures become cemetery
particles, not silent retries. Every queried candidate remains in its arm's
archive even if its lineage is later lost. Distinguish this archive from the
terminal weighted draw.

Primary development comparison: new best score and top-ten mean versus the
same-generator reference arm. Also report per-boundary score changes, resampling,
distinct retained ancestry, completed/failed option census, intended/realized
change, ring/cycle deltas, primitive depth and compute. A shared unchanged best
is a null result, not evidence that the next controller will work. This single
warm run does not support significance or robust superiority claims.

Maximum 72 new queries/tasks (the first nine tasks are shared), eighteen worker
containers plus one driver, no retries or training. Each worker: one CPU, 8 GiB,
240-second timeout. Driver: one CPU, 8 GiB, 1,200-second timeout. Observed preceding
replacement proposals took 23–102 seconds. Expected wall time 4–10 minutes plus
deployment; approximate cost $1–8, not a billing guarantee. Worst-case reserved
CPU bound 5.14 hours. Stop at four boundaries, budget exhaustion, unsupported
state, provenance mismatch or execution failure. Restart only compatible saved
workers; unresolved oracle reservations fail closed.

Operational repair: prevent an overdue periodic flush plus immediate forced
flush for the same immutable receipt. Serialize/recheck periodic flush decisions
so a heartbeat waiting on a recent barrier does not force a redundant commit.
Preserve durable parent/candidate locks and both oracle reservation/result
barriers. Use focused concurrency and accounting tests, then measure real commit
count/time in this reusable run. Do not claim a remote speedup from fixtures.

Authority is the continuing user-requested PMO controller goal and bounded
development/parallel-compute approval. Use a clean committed source revision,
preflight, deployment and durable spawn. No dirty-source exception, retraining,
gate relaxation, winner endpoint injection or launch beyond this census.
