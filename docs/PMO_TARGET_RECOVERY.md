# Answer-known PMO target recovery

The current user request authorizes a target-informed development diagnostic, not
a change to the frozen optimizer or a claim of blind discovery. The generated
object is a sequence of supported primitive edits from a saved persistent-slot
state to one manually transcribed public IVG molecule. The question is whether
that specific route can be executed, not whether the stochastic controller will
discover it. Executor support and the 40-active/48-slot, charge-preserving,
achiral representation remain unchanged. No reference model is trained.

The locked example is the first reward-labelled perindopril-MPO molecule in the
public plot, not its differently structured cell labelled Target. Its two fused
aromatic five-membered rings and saturated five-plus-six system were compared
with the drawing. An initial unscored exploratory transcription omitted a carbon
from the saturated system and produced a four-membered ring; it was rejected
before this lock. The retained SMILES is still a manual transcription, not an
author-supplied machine-readable record. The plot is not linked to a particular
no-prescreen run.

The configuration locks two new deterministic objective calls: the already scored
current best as a local evaluator parity check, and the public example. Search
then uses that same target from the current best and all four original roots,
without additional oracle calls. Source states are decoded from their exact
archives. RDKit SMILES correspondences are transported to existing slots and do
not reconstruct a saved molecular state.

Use the existing difference-directed bounded path compiler and record every
outcome. A found route is an upper bound on primitive path length, not proof of a
shortest route, positive learned transition probability, macro applicability, or
controller success. A search limit is an unresolved result, not an impossibility
claim. There are no performance baselines in this capability diagnostic; the
balanced same-generator baseline remains required for subsequent blind search.

Any future optimizer designed with this example is developed on this task.
Generalization must be tested on separate, uninspected objectives or sources.
Numerical outputs and execution instructions live in
`diagnostics/pmo_public_winner_recovery/` after running the locked diagnostic.
