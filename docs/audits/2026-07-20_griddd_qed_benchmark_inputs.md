# GrIDDD QED Benchmark Input Freeze

**Decision:** the public Jin et al. QED test list is exactly recoverable, but the
800-row artifact actually generated by the released GrIDDD preprocessing is
not.  We therefore freeze both (a) the exact public Jin list and (b) a clearly
named GrIDDD-code reconstruction, but authorize neither as the **exact GrIDDD
800**.  No primary benchmark model launch is authorized until that identity is
resolved or the authors provide the generated artifact.

## What the primary releases establish

The [GrIDDD paper](https://arxiv.org/abs/2506.15725) describes the constrained
QED optimization task as 800 molecules from the Jin et al. ZINC test suite with
starting QED in `[0.70, 0.80]`, 20 generated candidates per start, and success
when at least one candidate has QED in `[0.90, 1.00]` and fingerprint Tanimoto
similarity at least `0.40` to the start.

The [released GrIDDD preprocessing at the frozen
commit](https://github.com/mninniri/GrIDDD/blob/cc3dc31ac341216a0bbcc62f63ae6831581ff40b/griddd/datasets/zinc250k_dataset.py)
does not read the public Jin test file. It downloads the ZINC property CSV,
shuffles it with pandas `random_state=42`, makes an 80/10/10 split, preprocesses
the final test split, removes reconstructed test molecules found in the
processed training SMILES, and takes the first 800 retained test rows whose QED
lies in the closed interval. The repository does not contain the resulting
`new_test.smiles`, `qed_smiles.smiles`, or processed `test_qed` tensor.

The release also leaves an executed-configuration ambiguity. Its README asks
for `features.charges_policy="dictionary"` on ZINC, while the resolved experiment
configuration defaults to `partial`, and no run manifest binds the preprocessing
output to the documented RDKit 2023.03.2 environment. These choices can change
which rows survive the graph round trip.

The metric implementation is unambiguous: `rdkit.Chem.QED.qed` and Tanimoto
similarity between Morgan bit vectors with radius 2, 2048 bits, and chirality
disabled. COMPOSE's modern RDKit Morgan-generator API produced bit-identical
fingerprints for all 1,600 frozen exact/reconstruction rows.

## Wording correction

The statement “GrIDDD takes lead molecules with QED 0.70–0.80 and re-engineers
them to achieve a QED above 0.90 under Tanimoto similarity at least 0.40” is
substantively close, but two changes make it exact:

> In the GrIDDD QED molecular-optimization evaluation, 800 starting molecules
> with QED in the closed interval `[0.70, 0.80]` are each given 20 candidate
> generations. A start is successful if at least one candidate has QED in
> `[0.90, 1.00]` and Morgan-fingerprint Tanimoto similarity `>= 0.40` to the
> start.

This is an evaluation success criterion, not a hard structural constraint
enforced at every intermediate denoising/editing state. “At least 0.90” is also
more accurate than “above 0.90.” The fingerprint definition is in the released
repository, while the numerical task definition is supported by the paper and
release together.

## Fairness boundary

Protocol A is the only primary GrIDDD-comparable COMPOSE result: exact official
leads, 20 native direct-conditioned candidates, no successor-oracle tilt, no
beta-zero shadow rescoring, and benchmark evaluation calls separated from
native sampling cost. It is currently blocked because the exact GrIDDD lead
artifact is unavailable.

Protocol B is the internal mechanism study: direct, controller, and combined
arms with matched random streams and the existing exact 981-QED-call ledger per
start/seed/arm. Selection-influencing and padding calls remain separate. Its
table must never be described as query-matched to GrIDDD unless the external
baseline is rerun under the same budget.
