# Anytime credit for completed options

2026-09-09. The user authorized making the controller chain useful ring building,
restatement and other edits efficiently. This is a new opt-in development
controller policy, not a reinterpretation or resumed run of the frozen negative
16-edit terminal-only experiment. COMPOSE remains an executable graph rewrite
process. Its output here is a trajectory of complete supported graphs and a
pool of completed-option candidates.

## Problem and declared change

The hierarchical adapter harvests completed options before the final primitive
step, but the planner currently credits only the exact final step. A useful
intermediate option completion followed by a poor edit can therefore give zero
credit to the entire route. Source inspection establishes this mismatch; it
does not establish how often the saved production run encountered it.

Define G(x) as the existing round-frozen docking desirability multiplied by the
unchanged endpoint acceptance predicate. Already archived molecules receive
zero new-candidate utility. At completed option boundaries along a sampled
suffix, use the maximum G, including its final endpoint. The new
`anytime_options_v1` return policy estimates

    V(s) = E_reference[max{G(x_j): eligible completion j in the suffix from s}].

Back up a completed sampled suffix with U_i = max(g_i, U_(i+1)). For adaptive
planning, retain the actual suffix reference/proposal likelihood ratio when
adding U_i to its return estimate; lazy reference draws have ratio one.
Keep the full reference row, existing shrinkage, KL<=1 and exploration floors.
This is a sampled best-observed-endpoint criterion, not an exact optimal-stopping
Bellman solver, unbiased self-normalized estimate or calibrated uncertainty.
It does not reward ring count or the number of harvested states. The trajectory
budget bounds opportunities; report compute and candidate budgets in comparisons.

An unacceptable intermediate may still lead to a valuable later completion.
Partial/interrupted rollouts supply no fabricated suffix returns. Ordinary
option completion returns to WHERE, so construction, modification and another
construction remain possible. Planning continues through low-value completions;
this is not greedy early stopping or a reset of the remaining edit budget.

Only `executable_intermediates_v1` is allowed with the new return policy. Final
quality, QED, SA and original-seed similarity screens are unchanged. Preserve
legacy configuration serialization, return semantics and archived evidence.
The default remains historical; new preparations must explicitly opt in.

## Scope and acceptance

No change to R_theta, executor, priors, option menu, generic, kappa, frozen
predictor recipe, molecular support or the 16-edit development horizon. No
winner structures, paths, fragments, frequencies or labels enter this policy.
No new training, deployment or paid docking campaign belongs to this repair.

Minimal checks: early useful completions are credited despite a poor final
state; later improvement through a low-value completion is still credited;
suffix returns do not inherit already-past rewards; interruption does not publish
partial estimates; both lazy and adaptive planning preserve floors and KL;
legacy serialization/replay and final candidate screening remain intact.
Demonstrate a two-ring sequence separated by a modification with the existing
production executor, labelling any prescribed choices and model-free law as
capability evidence only, not autonomous discovery or docking guidance.

Run focused dependency tests from clean committed source. Reuse exact saved
inputs for numerical diagnostics; never regenerate the original winner paths.
Use local pinned-runtime feature checks before applying the saved T4 value model.
If runtime equivalence is absent, abstain from real task-value conclusions.
An actual frozen-model, matched-compute preparation comparison remains necessary
before claiming this change improves search. A null result must stay null.

## Immediate empirical capability probe

Before another learned-law preparation, run eight local model-free trajectories:
two sources (original PARP1 seed0 and the lowest-docking feasible member of the
complete 51-call archive), two fixed sequences, and RNG seeds 0 and 1. Sequences:
fused nonaromatic C6, local modification, pendant aromatic C4N1 five-ring; and
pendant nonaromatic C5O1 six-ring, local modification, fused aromatic C4N1
five-ring. These descriptors already exist in the parameterized option registry.
Choose the largest enumerated region of at most 24 atoms at each option, with
deterministic key tie-breaking. This prescribed WHERE/WHAT choice is capability
evidence, not a sampled controller draw or a fitted construction preference.

Use the production semantic executor, existing neutral broad-organic primitive
candidate descriptors for birth/bond-order edits/closure, and uniform diagnostic
mark weights. Raw closure descriptors are passed as typed semantic CycleCloseEdge
actions to that executor. This narrowly declared diagnostic law is NOT R_theta,
does not establish learned support mass, and is not an optimizer replacement.
The local stage tests bond-order modification; atom-type optimization is not
measured here. Each sequence has 12 committed primitive edits if completed.
No retries or substitutions after failed stages; keep every attempted trajectory.

Score each completed option using the unchanged T4 properties and the frozen
51-label docking predictor. Before any predictions, require the pinned RDKit and
NumPy versions, equality of all saved training features, and equality of stored
property/prediction records from the previous production lock. Report exclusions,
exact states/marks, ring sizes/cycle rank, diversity, timing and predictor scores
separately from actual docking. Use one CPU process with no accelerator, no model
fitting and zero oracle calls. Expected local runtime is seconds to a few minutes,
not a production throughput claim. Hard elapsed stop is 120 seconds for molecular
work, checked between primitive steps; an in-flight executor call may overrun it.
Reuse input-hashed completed trajectory receipts on restart. Do not repeat a
completed trajectory for logging or unrelated source changes.
