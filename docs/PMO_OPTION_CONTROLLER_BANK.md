# Balanced option-boundary continuation bank

Status: preparation contract. No remote proposal or task-oracle evaluation is
authorized by this document.

## Question

The locked complete-plan assay found a `0.0112784407` champion gain, but all
three parent improvements came from two source structures and from short local
plans. The existing actor ranked the eventual champion second among the 95
locked candidates. This establishes a sparse local ranking signal, not the
multi-option future evidence required by the persistent controller.

The next experiment asks one narrower question: does the production
WHERE/WHAT/HOW process, run under its balanced reference policy from strong
development parents, produce enough improving and non-improving complete-option
continuations to support a source-grouped future-value gate?

## Frozen preparation

- Task: exposed warm-development `perindopril_mpo`.
- Parents: the eight highest-scoring distinct exact source states in the
  complete 95-candidate assay. Ties are broken by canonical molecular identity.
- Independent streams: two per parent, 16 total.
- Horizon: three complete option boundaries. The primitive allowance is 96,
  but the scientific clock is the three-option horizon.
- WHERE: the qualified production region law.
- WHAT: the applicability-balanced reference option law. A zero actor makes
  proposal and reference probabilities identical. `generic` remains mandatory.
- HOW: the production option continuation kernel under its reference law.
- Enabled support: generic, parameterized pendant and fused rings, ring
  expansion, carbonyl options, and region replacement when applicable.
- Disabled: the unresolved 11-step `BUILD_RING_SYSTEM` compound option.
- Resampling: none. This is behavior-policy data collection, not a claim that an
  unvalidated value head improves search.
- Candidate rule: retain every complete option-boundary state, preserve exact
  persistent-slot state and ancestry, and canonical-deduplicate only for oracle
  accounting.

The immutable preparation binds the complete-plan report, one deterministic
source trace for each selected parent, the full matching-trace census, the exact
input state, parent score, source identities, code revision, seed derivation,
and package identity. SMILES are identity metadata, not a source from which
persistent states are reconstructed.

## Proposed remote computation, not yet authorized

The proposal-only run has 16 independent worker tasks and at most one driver.
Each worker advances one exact particle through at most three complete options.
The expected workload is comparable to 48 one-option tasks. Based on the prior
78-task option-particle run, expected proposal wall time is 4 to 10 minutes,
with a hard 20-minute driver limit, no GPU, no oracle, no retries, and at most
16 worker containers.

After the complete candidate lock exists, the exact count of previously
unscored canonical molecules, at most 48, becomes the only permissible request
for a later PMO oracle authorization. Scoring must be a separate command and
must never occur inside the proposal workers.

## Prespecified evidence gate

For each boundary state, a later scorer records the exact task utility and the
best improvement reached within each remaining option horizon. Right-censored
continuations remain unidentified rather than being labeled negative.

The bank is sufficient for the first source-grouped distributional-value fit
only if all of the following hold:

1. at least three distinct parent source groups contain a positive improvement;
2. both improving and non-improving identified cells exist at horizon one and
   at at least one longer horizon;
3. at least two non-generic option families complete, and no single option
   family supplies more than 80% of identified positive cells;
4. exact replay, candidate-lock, behavior-policy, and oracle accounting checks
   pass.

If the gate passes, fit the distributional option value with source-grouped
validation, then test it as a persistent-particle twist. If it fails because
the balanced policy rarely produces improvements, do not fit or scale SMC.
Repair the option proposal using the observed completed-option contrasts. If
the proposal run itself lacks option/topology coverage, repair applicability or
HOW completion before buying labels.

## Claim boundary

This is policy-congruent data collection on exposed development chemistry. It
is not PMO area under the curve, a matched InVirtuoGen comparison, prospective
generalization, or evidence that learned Doob control works. The task oracle is
used only after a frozen candidate lock and only under a later exact call
authorization.
