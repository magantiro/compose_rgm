# Donor/reference mixture: matched prescreened development

2026-09-11, locked before these outcomes. The preceding isolated donor probe
improved best score from 0.5595028849441883 to 0.5705974021574557 and top-ten
mean from 0.5366184196978077 to 0.5505935555447155. It queried 94 new molecules,
revalidated 100 historical labels, and recorded 30.8836 seconds of proposal work.
97/128 attempted programs compiled and independently replayed. It is not a
full-controller comparison, and learned-reference support was not certified.

Question: does adding this executable proposal channel improve the actual
queried archive versus the existing broad option controller from identical
prescreened starts? Output: two 16-particle populations, six option boundaries,
at most 192 new physical PMO queries. Both start from the first 16 exact states
of the original, score-ordered top-100 bank. Do not inject the probe's new best
as a start or donor. Its 94 scored endpoints can be reused only if independently
proposed again; those labels remain explicit prior development information.

Baseline: existing WHERE/WHAT/HOW broad option law including generic, carbonyl
and region replacement, unchanged R_theta and executor. Hybrid: with probability
1/2 use precisely that proposal; otherwise select a donor uniformly from the
original top-100 bank and one oriented single-bond bridge uniformly on each
molecule, then compile the transplant. No retry after size/charge/self/compile
failure. A failed option has zero continuation mass under the common SMC rule.
The 64-primitive ceiling applies to both arms. A whole compiled transplant is
one controller decision and its actual primitive count remains recorded.

This is an explicit proposal-law change, not a kappa change in the frozen
qualified controller. Donor paths use the unchanged executor but are not claimed
to have positive probability under R_theta's narrower deployed tables. They
have their own region allocation over bridge-defined pendant components;
generic editing retains the original local-to-global WHERE law. Report intended
released fraction and actual persistent-lineage displacement separately. No
finite molecular vocabulary is installed: the fixed bank defines this experiment's
donor distribution, while the reference channel retains broad atom/bond editing.

Both arms use the existing actual-score SMC at beta=10, systematic resampling
when ESS<N/2 at nonterminal boundaries, unchanged weight/potential bookkeeping,
and an archive of all queried complete candidates. This is not a learned future
value test. Different proposal path laws mean it is not a matched exact-Doob
target distribution. Best/top-ten optimization and the terminal particle draw
are separate outputs. Candidates are locked before each score batch; results
from a boundary cannot change its still-running proposals.

Original prescreen: 249455 reported historical labels with incomplete modern
provenance. The original bank's 100 usable labels have current-oracle parity.
Also disclose the prior 100 parity evaluations and 94 development endpoint

requested candidates are reported separately. This is an exposed prescreened
development comparison, not no-prescreen PMO, 10k-query AUC or external SOTA.

Compute: one CPU/8 GiB per worker, at most 29 workers plus one driver (30 total),
192 tasks, 180-second worker and 900-second driver limits, no retries or GPU.
Maximum CPU reservation 9.85 hours; $10 reserved cap, expected substantially

Expected 4–10 minutes, not guaranteed. Every completed worker is restart-safe,
with 30-second heartbeats and exact source/contract bindings. Deploy then spawn
from clean committed code. Focused checks only at this development boundary.

Decision: best improvement over both initialization and baseline earns a fresh
seed replication before increasing budget or transfer. A top-ten-only gain is
local refinement evidence. No improvement stops the unchanged mixture. High
failure/extinction rates diagnose this specific sampling rule, not impossible
chemistry. Report all failures and any timeout; do not rescue or weaken a gate.
