# Adaptive program search: first local batch

Measured structural result: 16 new eligible endpoints in 4.23 seconds of proposal
work, after replaying the 54-representation / 27-endpoint paid bank. These are
locked but **unscored**. No new docking or model-training calls were made.

`attempt_1/result.json` records input and implementation hashes, code revision,
configuration, all counts, timing, software, hardware and limitations.
`attempt_1/batch.json` retains the complete candidates and every attempted
proposal's outcome. `attempt_1/snapshot.json` preserves the pending lock, measured
archive, RNG and exact construction state for score ingestion and continuation.

Among 75 attempts, 16 were eligible and new, 18 duplicates, 13 ineligible and 28
failed. Ten failures were broad draws without the remote learned-reference
runtime; they were not reallocated. Thirteen candidates came from coherent
mutation, three from branch recombination. Ten changed two sites, six one.
The executor and endpoint criteria were unchanged.

Interpretation: coordinated programs now support variable attachments, created
atom identities, segment length, and branch combinations outside the original
bank. This result does **not** establish docking improvement or adaptive-policy
superiority. Static and adaptive initial distributions are identical until new
measured outcomes arrive. The same-source winning routes and paid labels are
declared development information, not source-held-out evaluation.

against a same-support static control. The proposed 108-call campaign requires
its separate budget decision. No remote follow-on is running. See
`docs/ADAPTIVE_PROGRAM_OPTIMIZER.md` for the runnable prepare/observe/resume path.
